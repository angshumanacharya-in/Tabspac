Add Two Numbers (LeetCode 2)

Introduction

Add Two Numbers is one of the most famous linked list problems on LeetCode. It is considered a classic interview question because it combines several fundamental programming concepts:

  • Linked Lists
  • Digit-by-digit arithmetic
  • Carry handling
  • Iterative traversal
  • Pointer manipulation

Although the problem statement is simple, it teaches an important technique that appears in many linked list interview problems.

Problem Statement

You are given two non-empty linked lists representing two non-negative integers. Each node contains exactly one digit. The digits are stored in reverse order.

Example Overview

The number 342 is stored as 2 → 4 → 3.
Similarly, 465 is stored as 5 → 6 → 4.

Your task is to add these two numbers and return the result as a linked list in the same reverse-order format.

Constraints

  • Both numbers do not contain leading zeros.
  • Each node stores a single digit (0–9).
  • The lists can have different lengths.

Understanding the Reverse Order

This is the most important observation. Normally, the number 342 is read left-to-right (Hundreds: 3, Tens: 4, Ones: 2). But the linked list stores it as 2 → 4 → 3.

Why? Because addition always starts from the least significant digit (the ones place). Instead of moving to the end of the linked list first, we can simply traverse directly from the head. This makes the problem much easier!

Examples & Visual Walkthrough

Example 1

l1 = 2 → 4 → 3 (Represents 342)
l2 = 5 → 6 → 4 (Represents 465)

Addition: 342 + 465 = 807

Output: 7 → 0 → 8 (Because 807 stored in reverse becomes 7 → 0 → 8).

Step-by-Step Breakdown

  • Step 1: 2 + 5 = 7. Carry = 0. Result so far: 7
  • Step 2: 4 + 6 = 10. Digit = 0, Carry = 1. Result so far: 7 → 0
  • Step 3: 3 + 4 + Carry(1) = 8. Carry = 0. Result: 7 → 0 → 8

Another Example (Handling End Carry)

Input: 9 → 9 → 9 and 1 (Represents 999 + 1 = 1000)

  • Step 1: 9 + 1 = 10. Store 0, Carry = 1
  • Step 2: 9 + Carry = 10. Store 0, Carry = 1
  • Step 3: 9 + Carry = 10. Store 0, Carry = 1

The lists are finished, but a carry remains. Create one final node for the carry. Output: 0 → 0 → 0 → 1

Key Observation & Algorithm

The addition process is exactly the same as elementary school addition. For every digit:

  • Current Sum = Digit from List1 + Digit from List2 + Carry
  • Current Digit = Sum % 10
  • New Carry = Sum / 10

Repeat this process until both lists finish AND the carry becomes zero.

Algorithm Steps

  1. Create a dummy node.
  2. Keep a pointer pointing to the current result node.
  3. Initialize carry as zero.
  4. Traverse both linked lists simultaneously.
  5. Read current digits and compute their sum with the carry.
  6. Store the last digit (sum % 10) and update carry (sum / 10).
  7. Move pointers forward.
  8. If a carry remains after traversal, create one final node.
  9. Return the node after the dummy node.

The Dummy Node Technique

Instead of treating the first node separately, create a dummy node: 0 → NULL. Every new digit is attached after it.

For example, Dummy(0) → 7 → 0 → 8. Finally, you just return Dummy->next.

Advantages:

  • Cleaner code
  • No special conditional checks for the first node
  • It is a standard, highly common linked list pattern

Code Implementations

class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        ListNode dummy(0);
        ListNode* current = &dummy;
        int carry = 0;

        while (l1 || l2 || carry) {
            int sum = carry;

            if (l1) {
                sum += l1->val;
                l1 = l1->next;
            }

            if (l2) {
                sum += l2->val;
                l2 = l2->next;
            }

            carry = sum / 10;
            current->next = new ListNode(sum % 10);
            current = current->next;
        }

        return dummy.next;
    }
};
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        current = dummy
        carry = 0
        
        while l1 or l2 or carry:
            val1 = l1.val if l1 else 0
            val2 = l2.val if l2 else 0
            
            total = val1 + val2 + carry
            carry = total // 10
            
            current.next = ListNode(total % 10)
            current = current.next
            
            if l1: l1 = l1.next
            if l2: l2 = l2.next
            
        return dummy.next

Complexity Analysis

Resource Complexity Explanation
Time Complexity O(max(m, n)) Where m and n are the lengths of the two lists. Each node is visited exactly once.
Space Complexity O(1) Auxiliary space is constant (excluding the output linked list).

Common Mistakes

  • Forgetting the Final Carry: 999 + 1 requires 0 → 0 → 0 → 1. Many beginners forget to create the last node.
  • Ignoring Different Lengths: 123 + 99999. The algorithm must continue processing the longer list after the shorter one ends.
  • Not Using a Dummy Node: Without a dummy node, special handling is needed for the first node, making the implementation more error-prone.

Alternative Approaches

  • Recursive Solution: The addition can also be implemented recursively by passing the carry to each recursive call. It is elegant and concise, but uses additional recursion stack space.
  • Convert to Integer (Not Recommended): One might think of converting the linked lists into integers, adding them, and converting back. This approach fails because the numbers can be extremely large and may exceed the capacity of built-in integer types.

Interview Tips

During an interview, explicitly explain to your interviewer that:

  • Digits are stored in reverse order, allowing addition strictly from the head.
  • A carry variable tracks mathematical overflow accurately.
  • A dummy node simplifies linked list construction and edge cases.
  • The loop continues while either list has nodes or a carry remains.
  • The algorithm handles lists of unequal lengths naturally.

These observations demonstrate a clear understanding of both linked list data structures and arithmetic simulation.

Key Takeaways

  • Reverse-order storage eliminates the need to reverse the linked lists before processing.
  • Process one digit at a time, exactly like manual elementary addition.
  • Maintain a carry throughout the entire traversal.
  • A dummy node makes constructing the result list straightforward and safe from null pointer errors.
  • The solution runs in O(max(m, n)) time with O(1) auxiliary space.
