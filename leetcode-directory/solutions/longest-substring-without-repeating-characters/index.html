Longest Substring Without Repeating Characters (LeetCode 3)

Introduction

Strings are among the most frequently tested topics in coding interviews. One of the most famous string problems is Longest Substring Without Repeating Characters.

At first glance, the problem appears simple—you only need to find the longest substring containing unique characters. However, solving it efficiently requires understanding one of the most important algorithmic techniques: the Sliding Window.

This problem is asked by companies like Google, Amazon, Microsoft, Meta, Apple, Adobe, Uber, and many others because it tests:

  • String manipulation
  • Hash maps
  • Two pointers
  • Sliding window optimization
  • Time complexity analysis

Problem Statement

Given a string s, return the length of the longest substring without repeating characters.

A substring is a contiguous sequence of characters.

Example 1

Input: s = "abcabcbb"
Output: 3
Explanation: The answer is "abc", with the length of 3.

Example 2

Input: s = "bbbbb"
Output: 1
Explanation: The answer is "b", with the length of 1.

Example 3

Input: s = "pwwkew"
Output: 3
Explanation: The answer is "wke", with the length of 3.
Notice that "pwke" is a subsequence and not a substring, as the characters are not contiguous.

Understanding the Problem & Brute Force

Suppose we have "abcabcbb". Possible substrings starting at index 0 are:

  • "a"
  • "ab"
  • "abc"
  • "abca" [Duplicate found]

After reaching the second 'a', we cannot continue expanding. Instead of restarting from scratch, we should move our starting position forward. This observation naturally leads to the Sliding Window technique.

Brute Force Approach

The simplest idea is to generate every possible substring, check if it contains all unique characters, and track the maximum length.

  • Outer loop for starting index i
  • Inner loop for ending index j
  • Check if substring(i, j) consists of unique characters

Complexity: Generating all substrings takes O(n²) time, and checking uniqueness takes O(n). The overall time complexity is O(n³), which is far too slow for large inputs.

Sliding Window Concept

Instead of checking every substring independently, maintain one valid dynamic window using two pointers (left and right). Whenever a duplicate appears, shift the left pointer forward until the duplicate is removed.

Visual Walkthrough

Input: "abcabcbb"

  • Read 'a': Window = "a", Length = 1, Max Answer = 1
  • Read 'b': Window = "ab", Length = 2, Max Answer = 2
  • Read 'c': Window = "abc", Length = 3, Max Answer = 3
  • Read 'a': Duplicate 'a' found. Slide left pointer past the first 'a'. Window = "bca", Length = 3.
  • Continue: Windows become "cab", "abc", "cb", "b". Maximum length never exceeds 3.

Data Structure Used

We need to know whether a character already exists inside the current window and where it was last seen. We can use an unordered_map, a dictionary, or a fixed-size array of size 256 for ASCII characters.

Optimal Algorithm

  1. Initialize left = 0, ans = 0, and a hash map to store the last seen index of each character.
  2. Traverse the string with a right pointer.
  3. If the current character was seen before and its last recorded index is >= left, update left = lastSeen[ch] + 1.
  4. Update the character's last seen index in the hash map.
  5. Update maximum length: ans = max(ans, right - left + 1).

Code Implementations

class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        unordered_map<char, int> lastSeen;

        int left = 0;
        int ans = 0;

        for (int right = 0; right < s.size(); right++) {

            if (lastSeen.count(s[right]) &&
                lastSeen[s[right]] >= left) {

                left = lastSeen[s[right]] + 1;
            }

            lastSeen[s[right]] = right;

            ans = max(ans, right - left + 1);
        }

        return ans;
    }
};
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last_seen = {}

        left = 0
        answer = 0

        for right, ch in enumerate(s):

            if ch in last_seen and last_seen[ch] >= left:
                left = last_seen[ch] + 1

            last_seen[ch] = right

            answer = max(answer, right - left + 1)

        return answer

Complexity Analysis

Resource Complexity Explanation
Time Complexity O(n) Each character is visited at most twice (once by right and once when shifting left).
Space Complexity O(min(n, m)) Where m is the character set size. For standard ASCII characters, space is bounded by O(1).

Edge Cases & Common Mistakes

Edge Cases

  • Empty String: "" -> Output: 0
  • Single Character: "a" -> Output: 1
  • All Same Characters: "aaaaaa" -> Output: 1
  • All Unique Characters: "abcdef" -> Output: 6
  • Repeated Characters (e.g., "abba"): Output: 2

Common Mistakes

  • Resetting the window completely: Restarting traversal from scratch after finding a duplicate degrades performance back to O(n²).
  • Moving the left pointer backwards: Always ensure left = max(left, lastSeen[ch] + 1) or check lastSeen[ch] >= left before updating.
  • Confusing Substring with Subsequence: A substring must be strictly contiguous.

Interview Tips & Similar Problems

During an interview, make sure to explicitly explain:

  • Why the left pointer never moves backward.

Key Takeaways

  • Brute force takes O(n³) time; Sliding Window reduces complexity to O(n).
  • A hash map efficiently tracks the last occurrence of each character.
  • Checking lastSeen[ch] >= left avoids moving the left pointer backward incorrectly.
  • This problem is a classic foundation for all sliding window interview questions.
