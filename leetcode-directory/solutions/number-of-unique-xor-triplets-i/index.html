Number of Unique XOR Triplets I (LeetCode 3513)

Introduction

Bitwise XOR is one of the most interesting operations in computer science. Unlike addition or multiplication, XOR follows unique algebraic properties that often lead to elegant mathematical solutions.

In this problem, we are given a permutation of integers from 1 to n, and we must determine how many distinct XOR values can be produced by choosing any triplet of indices (i, j, k) where i ≤ j ≤ k.

The remarkable aspect of this problem is that, despite the enormous number of possible triplets (O(n³)), the solution requires only constant time.

Problem Statement

Given an array nums that is a permutation of integers from 1 to n, we may choose any indices satisfying i ≤ j ≤ k to calculate the XOR triplet:

nums[i] ⊕ nums[j] ⊕ nums[k]

Return the number of unique XOR values obtainable.

Example 1

Input: nums = [1, 2]
Possible XOR values:

  • 1 ⊕ 1 ⊕ 1 = 1
  • 1 ⊕ 1 ⊕ 2 = 2
  • 1 ⊕ 2 ⊕ 2 = 1
  • 2 ⊕ 2 ⊕ 2 = 2

Unique values: {1, 2}
Output: 2

Example 2

Input: nums = [3, 1, 2]
Some triplets:

  • 3 ⊕ 3 ⊕ 3 = 3
  • 3 ⊕ 3 ⊕ 1 = 1
  • 3 ⊕ 3 ⊕ 2 = 2
  • 3 ⊕ 1 ⊕ 2 = 0

Unique values: {0, 1, 2, 3}
Output: 4

Constraints

  • 1 ≤ n ≤ 100000
  • nums is a permutation of numbers 1 ... n.

A brute-force solution is clearly impossible given n = 100000.

Understanding XOR

The XOR operator has several important properties:

  • Property 1: A number XOR itself becomes zero (x ⊕ x = 0). Example: 5 ⊕ 5 = 0.
  • Property 2: Zero does not affect XOR (x ⊕ 0 = x).
  • Property 3: Therefore, x ⊕ x ⊕ y = y.

This self-canceling property is the key observation.

Case Analysis: What Does i ≤ j ≤ k Mean?

Indices may repeat. Patterns like (i, i, i), (i, i, j), (i, j, j), and (i, j, k) are all valid.

Case 1: All indices equal

a ⊕ a ⊕ a = (a ⊕ a) ⊕ a = 0 ⊕ a = a
Every element itself is always obtainable.

Case 2: Two indices equal

a ⊕ a ⊕ b = 0 ⊕ b = b
No new XOR value is created beyond what is already in the original array.

Case 3: Three different elements

Only a ⊕ b ⊕ c can generate genuinely new XOR values.

Why Order Does Not Matter

XOR is both commutative (a ⊕ b = b ⊕ a) and associative ((a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)). Thus, 1 ⊕ 5 ⊕ 7 = 7 ⊕ 1 ⊕ 5.

Binary Representation & Reachability

Suppose n = 10. The largest value is 10, which in binary is 1010 (requiring 4 bits). Therefore, every XOR result must also fit within 4 bits.

Possible values range from 0000 to 1111 (0 to 15), giving exactly 16 possible values.

General Rule

Let bits = floor(log₂(n)) + 1. Every possible XOR value lies in 0 to 2ᵇⁱᵗˢ − 1, giving a total of 2ᵇⁱᵗˢ possibilities.

Why Are All These Values Reachable?

Since nums contains every integer from 1 to n exactly once, it provides a dense set of bit patterns. For n ≥ 3, XOR combinations of three elements can generate every single bit pattern in the range 0 to 2ᵇⁱᵗˢ − 1.

Special Cases (n < 3)

For n = 1, answer = 1.
For n = 2, numbers are {1, 2}. Possible XOR values are 1 and 2 (zero cannot be produced). Answer = 2.

Code Implementations

class Solution {
public:
    int uniqueXorTriplets(vector<int>& nums) {
        const int n = nums.size();

        if (n < 3)
            return n;

        return 1 << (static_cast<int>(std::log2(n)) + 1);
    }
};
import math

class Solution:
    def uniqueXorTriplets(self, nums: list[int]) -> int:
        n = len(nums)
        
        if n < 3:
            return n
            
        bits = math.floor(math.log2(n)) + 1
        return 1 << bits

Complexity Analysis

Resource Complexity
Time Complexity O(1) – Computing log2(n) takes constant time.
Space Complexity O(1) – Only a few local variables are used.

Key Takeaways

  • XOR has a self-canceling property: x ⊕ x = 0.
  • Repeated indices do not introduce new XOR values because x ⊕ x ⊕ y = y.
  • The maximum number n dictates the total number of bits required for any XOR combination.
  • For any permutation of 1 to n with n ≥ 3, every bit pattern representable within those bits can be achieved.
  • This leads to an optimal O(1) solution: if n < 3, return n; otherwise return 2ᵇⁱᵗˢ.
