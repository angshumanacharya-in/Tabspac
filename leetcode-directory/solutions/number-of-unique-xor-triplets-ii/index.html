Number of Unique XOR Triplets II (LeetCode 3514)

Introduction

Bitwise XOR is one of the most interesting operations in computer science. Unlike addition or multiplication, XOR has several unique mathematical properties that make many seemingly difficult problems surprisingly elegant[cite: 1].

In this problem, we are asked to determine how many distinct XOR values can be produced by selecting three elements from an array while respecting the index ordering[cite: 1].

Although the brute-force approach appears straightforward, it quickly becomes infeasible because of the large input size. The key observation is that the XOR values themselves have a very small range, allowing us to use dynamic programming over XOR states[cite: 1].

Problem Statement

You are given an integer array nums[cite: 1].

A XOR triplet is defined as[cite: 1]:

nums[i] XOR nums[j] XOR nums[k][cite: 1]

where[cite: 1]

i ≤ j ≤ k[cite: 1]

Return the number of unique XOR values that can be formed from every possible triplet[cite: 1].

Example 1

Input: nums = [1, 3]
Output: 2
Explanation: Possible triplets yield values {1, 3}[cite: 1].

Example 2

Input: nums = [6, 7, 8, 9]
Output: 4
Explanation: Unique XOR values are {6, 7, 8, 9}[cite: 1].

Understanding XOR & Important Observations

The XOR operation has several important properties[cite: 1]:

  • a ^ a = 0[cite: 1]
  • a ^ 0 = a[cite: 1]
  • a ^ b = b ^ a[cite: 1]
  • (a ^ b) ^ c = a ^ (b ^ c)[cite: 1]

Index Conditions & Cases

Since indices satisfy i ≤ j ≤ k, indices may repeat[cite: 1]. There are three different situations[cite: 1]:

  • Case 1 (All three indices identical): x ^ x ^ x = x. Produces an existing array value[cite: 1].
  • Case 2 (Exactly two indices identical): x ^ x ^ y = y or x ^ y ^ y = x. Also produces values already present in the array[cite: 1].
  • Case 3 (Three distinct indices): a ^ b ^ c. These are the only triplets capable of generating completely new XOR values[cite: 1].

Therefore, we only need every original array value and every XOR obtainable using three distinct elements[cite: 1].

Why Brute Force Doesn't Work

A direct solution checks every triplet using three nested loops, giving an O(n³) complexity[cite: 1]. For n = 1500, this means 1500³ = 3.375 billion triplets, which is far beyond acceptable limits[cite: 1].

The Key Insight

Notice that nums[i] ≤ 1500. Since 1500 < 2¹¹, every value fits inside 11 bits[cite: 1]. Therefore, the maximum XOR value is 2047, meaning there are only 2048 possible XOR results[cite: 1]. Instead of tracking millions of triplets, we only track these possible XOR values[cite: 1].

Dynamic Programming Approach

We define three DP arrays[cite: 1]:

  • dp1[x]: True if XOR value x can be formed using one distinct element[cite: 1].
  • dp2[x]: True if XOR value x can be formed using two distinct elements[cite: 1].
  • dp3[x]: True if XOR value x can be formed using three distinct elements[cite: 1].

DP Transition & Backward Updates

For each number v in nums[cite: 1]:

  • Build triples: If dp2[x] is true, then x ^ v forms a triple (`dp3[x ^ v] = true`)[cite: 1].
  • Build pairs: If dp1[x] is true, then x ^ v forms a pair (`dp2[x ^ v] = true`)[cite: 1].
  • Build singles: Simply mark dp1[v] = true[cite: 1].

Why We Update Backwards: Updating from triples down to singles ensures that the current element is not reused multiple times in the same iteration[cite: 1].

Code Implementations

class Solution {
public:
    int uniqueXorTriplets(vector<int>& nums) {
        const int MAXX = 2048;

        vector<bool> dp1(MAXX, false);
        vector<bool> dp2(MAXX, false);
        vector<bool> dp3(MAXX, false);

        for (int v : nums) {
            // Build triples
            for (int x = 0; x < MAXX; x++) {
                if (dp2[x])
                    dp3[x ^ v] = true;
            }

            // Build pairs
            for (int x = 0; x < MAXX; x++) {
                if (dp1[x])
                    dp2[x ^ v] = true;
            }

            // Single element
            dp1[v] = true;
        }

        int ans = 0;
        for (int x = 0; x < MAXX; x++) {
            if (dp1[x] || dp3[x])
                ans++;
        }

        return ans;
    }
};
class Solution:
    def uniqueXorTriplets(self, nums):
        MAXX = 2048

        dp1 = [False] * MAXX
        dp2 = [False] * MAXX
        dp3 = [False] * MAXX

        for v in nums:
            # Build triples
            for x in range(MAXX):
                if dp2[x]:
                    dp3[x ^ v] = True

            # Build pairs
            for x in range(MAXX):
                if dp1[x]:
                    dp2[x ^ v] = True

            # Single element
            dp1[v] = True

        ans = 0
        for x in range(MAXX):
            if dp1[x] or dp3[x]:
                ans += 1

        return ans

Complexity Analysis

Resource Complexity Explanation
Time Complexity O(n × 2048) For each element, we iterate through all 2048 XOR states. Since 2048 is a constant, it runs in O(n) practical time[cite: 1].
Space Complexity O(2048) Constant space required for the fixed-size DP arrays[cite: 1].

Key Takeaways

  • Repeated indices never create new XOR values because of the cancellation property of XOR[cite: 1].
  • Only triplets consisting of three distinct elements need to be explored for new results[cite: 1].
  • The small XOR range (0–2047) makes dynamic programming over XOR states highly efficient[cite: 1].
  • This elegant solution reduces the problem from an impractical O(n³) brute force to an efficient O(n × 2048) algorithm[cite: 1].
