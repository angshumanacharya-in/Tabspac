Two Sum – A Complete Guide

Introduction

Two Sum is the very first problem on LeetCode (Problem #1) and one of the most famous coding interview questions. Although it is categorized as an Easy problem, it introduces a fundamental technique used in many advanced algorithms: using a hash table to trade space for time.

The problem tests your understanding of arrays, searching, and efficient data structures. It is commonly asked in technical interviews by companies such as Google, Amazon, Microsoft, Meta, and Apple.

Problem Statement

Given an array of integers nums and an integer target, return the indices of the two numbers such that they add up to the target.

You may assume that:

  • Exactly one valid solution exists.
  • You may not use the same element twice.
  • The answer can be returned in any order.

Example 1

Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: nums[0] + nums[1] = 2 + 7 = 9

Example 2

Input: nums = [3,2,4], target = 6
Output: [1,2]

Example 3

Input: nums = [3,3], target = 6
Output: [0,1]

Understanding the Problem

Suppose we have nums = [2,7,11,15] and target = 9. We need to find two numbers whose sum equals 9.

Instead of trying every possible pair, we can ask: "For the current number, what number do I need to complete the target?"

For example, if Current Number = 2, then Needed Number = 9 − 2 = 7. If 7 already exists in the array (and we've seen it while scanning), then we've found the answer.

Approach 1: Brute Force

The simplest solution is to compare every pair (e.g., 2+7, 2+11, 2+15, 7+11, etc.). If any pair equals the target, return their indices.

Algorithm

  • Choose the first element.
  • Compare it with every remaining element.
  • If their sum equals the target, return the indices.
  • Otherwise continue.

Complexity

  • Time Complexity: O(n²)
  • Space Complexity: O(1)

Why Brute Force Is Slow

Imagine 1000 numbers. The algorithm compares nearly every pair, leading to approximately 1000 × 1000 ≈ 1,000,000 comparisons. This quickly becomes inefficient.

Approach 2: Hash Map (Optimal)

Instead of repeatedly searching the array, we store numbers we have already seen in a hash map (Value → Index). Searching in a hash map takes roughly O(1) time, which is much faster than searching an array.

Key Idea

For every number Current = nums[i], compute Needed = Target − Current. If Needed already exists in the hash map, return [Stored Index, Current Index]. Otherwise, store Current Number → Current Index inside the map.

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> mp;

        for (int i = 0; i < nums.size(); i++) {
            int need = target - nums[i];

            if (mp.count(need))
                return {mp[need], i};

            mp[nums[i]] = i;
        }

        return {};
    }
};
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        mp = {}
        
        for i, num in enumerate(nums):
            need = target - num
            
            if need in mp:
                return [mp[need], i]
                
            mp[num] = i
            
        return []

Complexity Analysis

Approach Time Complexity Space Complexity
Brute Force O(n²) O(1)
Hash Map (Optimal) O(n) O(n)

Common Mistakes

  • Using the Same Element Twice: You cannot use the same index twice (e.g., target = 6, nums = [3]).
  • Storing Before Checking: If you insert the current element before checking for its complement, you may accidentally match the same element.
  • Returning Values Instead of Indices: The problem asks for array indices, not the actual values.

Real-World Applications

  • Finding two transactions that total a specific amount.
  • Matching complementary inventory values.
  • Detecting pairs that satisfy financial constraints.
  • Searching for complementary values in large datasets.

Key Takeaways

  • The brute-force solution compares every possible pair and runs in O(n²) time.
  • The optimal solution uses a hash map to remember previously seen numbers in O(n) time.
  • The central idea is to search for the complement (target − current) instead of searching directly for another number.
  • Two Sum demonstrates how choosing the right data structure can dramatically improve performance.
